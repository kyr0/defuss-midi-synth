# Browser demo

The page is a DOS screen over Matrix rain (`style.css`, `player.css`). Its layout follows defuss-shadcn's record shop showcase: a site header, the release as the hero (the album's cover beside its title and tracklist), the crates of album sleeves pinned askew with their years on stickers, the instrument as a framed window, and a footer of columns. Text is set in VT323 and headings in Press Start 2P, both served from `fonts/` (OFL) rather than from Google. The page makes one third-party request: choosing the SoundFont engine fetches the OPL-3 FM 128M SoundFont from huggingface.co/kyr0/midi-synth. Corners are square, frames phosphor green, shadows hard and unblurred. Two of defuss-shadcn's shaders draw: `matrix` behind the page, whose speed follows the music's level and bass, and `crt`, which shows the album's cover in its own colors on a slightly curved, scanlined tube. The sleeves are pixelated in blocks of 2 CSS pixels by an SVG filter (`#px`) on their `<img>`: a shader instance draws into a canvas of its own, which 33 sleeves do not need for a still picture. Bergium's canvas fades in over the cover while music plays; it draws one pixel per 2 CSS pixels, which the canvas scales up as blocks.

VERIFIED: `app.js` uses the public built package under `synth/`, so the interactive demo exercises the delivered facade and AudioWorklet (`scripts/e2e.mjs`). The static page needs no backend. Uploaded music and SoundFonts stay in browser memory.

The bank and preset selectors list the active engine's presets. A drum kit of bank 128 plays on channel 10, every other preset on channel 1, through `selectPreset`. The piano maps pointer and keyboard input to MIDI events on that channel. Controls use acknowledged commands, so failures appear in the status line. The page records what the keys and Web MIDI keyboards play as MIDI messages with their times, the piano's preset first; a pause of more than two seconds with no note or pedal held shrinks to two seconds, so a recording left open does not grow into minutes of silence. Its download, and each track's WAV button, render on a separate offline synthesizer (`render.js`) with the engine and bank shown, a second of audio per step with a yield between steps, without disturbing the live one. Web MIDI input goes to `sendMidi` as it arrives; system messages are left out. The scope draws only while keys sound, from any source, and for 0.8 s after the last. The demo score is original material supplied with this project.

The music player (`player.js`, `player.css`) plays the albums of `music/index.json` (`scripts/index-music.mjs` writes it). Its controls are defuss-shadcn's Audio, Playlist Item, Toggle Group, Select and Slider markup and styles with the page's colors as tokens; `player.js` drives them itself, because the sound comes from the AudioWorklet and the Audio component's script drives an `<audio>` element. An analyser on the synthesizer's output sets the rain's speed: 0.6 in silence, up to 3 with loud music and a heavy bass. The shader's clock adds up its speed frame by frame, so a changed speed never makes the rain jump. On the FM engine each album plays with its game's bank from the index, and a list of all banks shows it; a bank the user picks holds until another album plays, and a WOPL file of the user's stays until the user picks a bank. An album's list holds the tracks of all its editions, so the page needs no edition selector. The bar at the bottom (`progress.js`, defuss-shadcn's Progress field) shows the library's `onProgress` events for files above 1 MB and the WAV renders. Selecting a track, the play button and the engine switch start audio themselves, so the page needs no separate power-on. The page labels the FM engine "Gravis Ultrasound" and the SoundFont engine "SoundBlaster 16", and opens on Age of Empires II, on the FM engine and with Bergium; its SoundFont engine loads the OPL-3 FM 128M SoundFont (104 MB compressed) from Hugging Face only when chosen, because GitHub Pages does not serve the Git LFS copy in `sf2_sb16/`. Albums whose files state a wrong clock carry a `tempo` in the index, which the player passes to `loadMidi`.

The progress bar is defuss-shadcn's Slider, whose script redraws the filled part only on the user's input: the player sets the fill itself, and holds the bar only while the user drags it, not while it has the focus.

The visualizer is Bergium (https://github.com/kyr0/bergium), vendored in `vendor/bergium/` because it is not published to npm. `demo/visualizer.ts` uses its low-level `createVisualizer` on one canvas; the page offers its Butterchurn pipeline ("Bergium") or none ("No Visuals"), Bergium by default. It hears the synthesizer's `source`, the signal before the volume slider, through a gain of 4, so the picture moves at any volume and four times as strongly as the output's level gave it. It rotates every 30 seconds through the 14 presets of `demo/bergium-presets.json`, which the build takes from butterchurn-presets' base pack into `visualizer/presets.json` (102 KB instead of the 646 KB pack), and shows each new track's title over the picture. The build bundles it into `visualizer/` (197 KB), which the page loads once audio runs.

The build copies defuss-shadcn's runtime and the stylesheets the page uses to `shadcn/`, with its licence. The page keeps its other controls in plain HTML, CSS and JavaScript; a framework would add a second build lifecycle for a single screen without reducing the audio implementation. `build.mjs` copies the package files to `synth/`; edits belong in `src/`, not there. The copy is committed, because GitHub Pages serves this folder from `main` without a build step, so a change to `src/` needs `make build` before its commit.
