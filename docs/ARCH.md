# Browser demo

The page is a DOS screen over Matrix rain (`style.css`, `player.css`). Its layout follows defuss-shadcn's record shop showcase: a site header, the release as the hero (the album's cover beside its title and tracklist), the crates of album sleeves pinned askew with their years on stickers, the instrument as a framed window, and a footer of columns. Text is set in VT323 and headings in Press Start 2P, both served from `fonts/` (OFL) rather than from Google. The page makes one third-party request: choosing the SoundFont engine fetches the OPL-3 FM 128M SoundFont from huggingface.co/kyr0/midi-synth. Corners are square, frames phosphor green, shadows hard and unblurred. Two of defuss-shadcn's shaders draw: `matrix` behind the page, whose speed follows the music's level and bass, and `crt`, which shows the album's cover in its own colors on a slightly curved, scanlined tube. The sleeves are pixelated in blocks of 2 CSS pixels by an SVG filter (`#px`) on their `<img>`: a shader instance draws into a canvas of its own, which 33 sleeves do not need for a still picture. Bergium's picture fades in over the cover while music plays, at 50% opacity, so the cover shows through; it draws one pixel per 2 CSS pixels, which the canvas scales up as blocks.

VERIFIED: `app.js` uses the public built package under `synth/`, so the interactive demo exercises the delivered facade and AudioWorklet (`scripts/e2e.mjs`). The static page needs no backend. Uploaded music, SoundFonts, WOPL banks and profile packs stay in browser memory.

The bank and preset selectors list the active engine's presets. A drum kit of bank 128 plays on channel 10, every other preset on channel 1, through `selectPreset`; the MT-32 profile plays them on channel 2, since its parts listen on channels 2 to 9 and channel 1 is silent. The piano maps pointer and keyboard input to MIDI events on that channel. Controls use acknowledged commands, so failures appear in the status line. The page records what the keys and Web MIDI keyboards play as MIDI messages with their times, the piano's preset first; a pause of more than two seconds with no note or pedal held shrinks to two seconds, so a recording left open does not grow into minutes of silence. Its download, and each track's WAV button, render on a separate offline synthesizer (`render.js`) with the engine and bank shown, a second of audio per step with a yield between steps, without disturbing the live one. Web MIDI input goes to `sendMidi` as it arrives; system messages are left out. The scope draws only while keys sound, from any source, and for 0.8 s after the last. The demo score is original material supplied with this project.

The music player (`player.js`, `player.css`) plays the albums of `music/index.json` (`scripts/index-music.mjs` writes it). Its controls are defuss-shadcn's Audio, Playlist Item, Toggle Group, Select and Slider markup and styles with the page's colors as tokens; `player.js` drives them itself, because the sound comes from the AudioWorklet and the Audio component's script drives an `<audio>` element. An analyser on the synthesizer's output sets the rain's speed: 0.6 in silence, up to 3 with loud music and a heavy bass. The shader's clock adds up its speed frame by frame, so a changed speed never makes the rain jump. On either FM engine, the OPL3 or the CQM, each album plays with its game's bank from the index, and a list of all banks shows it; a bank the user picks holds until another album plays, and a WOPL file of the user's stays until the user picks a bank. An album's list holds the tracks of all its editions, so the page needs no edition selector. The bar at the bottom (`progress.js`, defuss-shadcn's Progress field) shows the library's `onProgress` events for files above 1 MB and the WAV renders. Selecting a track, the play button and the Sound Engine controls start audio themselves, so the page needs no separate power-on. The page labels its engines by hardware profile and opens on Warcraft II, on the Sound Blaster 16 (OPL3) and with Bergium; its SoundFont engine loads the OPL-3 FM 128M SoundFont (104 MB compressed) from Hugging Face only when chosen or when an album that plays on it starts, because at 104 MB it exceeds GitHub's 100 MB file limit, so neither this repository nor GitHub Pages holds it. Albums whose files state a wrong clock carry a `tempo` in the index, which the player passes to `loadMidi`. Jazz Jackrabbit, Jazz Jackrabbit 2 and The Settlers II carry `engine: "sb16-opl3"` in the index, the author's choice, and their tracks start on that profile; other albums' tracks start on the page's default, currently the same profile. An engine the user picks, or loads a file into, holds until another album plays, as a picked bank does. The index holds this rather than `player.js`, beside each album's bank and tempo, so one file says how an album plays.

The Sound Engine section, above the player, has a button per engine and under it only the controls that engine needs. "Sound Blaster 16" plays libADLMIDI on one chip, with a switch between the OPL3 and the Creative CQM; it plays on the chip it played last. "SoundFont" plays TinySoundFont and names its SoundFont. Where the demo server provides E-mu's 2GMGSMT SoundFont (`profile-assets/pci128.sf2`, copyright E-mu Systems), that button reads "Sound Blaster 128" and plays that bank, as the human asked (2026-11-25); the public site has no copy, so there it plays the OPL-3 FM 128M SoundFont. "ROMs" shows a list of the devices that play with the user's files, five rows high, and plays the one chosen in it. Each control shows only for its engine, so a profile that needs files never shows a button that fails on the public site. Files dropped on the section, or chosen with the "Load pack" button, go through `File.arrayBuffer()` to `devicesIn` (`profile-files.js`), which finds the devices in them, so the bytes stay in the page. A `.dspack` counts by the model in its header. An ECW waveset is packed as the Sound Blaster PCI 128's pack. Loose Roland ROM files count once they make a complete set: they are identified by size and SHA-1 or SHA-256 against `roms.json`, which `scripts/build.mjs` writes from `scripts/roms/` (sizes and hashes, no ROM data), and packed with the roles `scripts/profile-assets.py` uses. Matching by hash instead of by name takes dumps under any name and refuses a wrong or byte-swapped file before a core sees it. Packs with the same bytes count once. A device is named by `packs.json`, which `scripts/packs-catalog.py` writes: each file name maps to a maker, model, year and the file's SHA-256, and an entry names a file only when its bytes have that hash. Keying by name alone would misname a default pack such as `roland-mt32.dspack`, which holds whichever revision was activated last. Without a matching entry a device gets its profile's maker, model and year from `devices.json`, with its ROM revision, its AWE bank's own name or its file name as the variant. The list runs newest release first and chooses the device that plays, else the first, and it sorts again after each drop. An AWE pack plays on its card's module, which builds only locally. `scripts/serve.mjs` (`make start`, and the e2e) serves the files of its `LOCAL_FILES` that exist, `profile-assets/local-builds/awe32.wasm`, `awe64.wasm` and `profile-assets/pci128.sf2`, under `/local/` and lists them in `/local/index.json`; the page asks for the list only on `localhost`, `127.0.0.1` or `[::1]`. These files stay out of `docs/`, because GitHub Pages serves `docs/` as tracked, the AWE driver has no licence to be distributed and the SoundFont is E-mu's; on the public site an AWE pack needs its `.wasm` dropped with it, and the list says so. A device chosen loads with `useProfile(profile, sources)`, and a second device of a loaded profile loads in its place while a file plays on. The page passes the sources of the device that plays to `render.js` for WAV downloads, and saves them with `openProfileStore()` in the origin private file system, one per profile; a later visit lists them as stored and plays one from there without asking for files. "Forget this device" takes the chosen device off the list and deletes its files where the store holds them (a stored device, or the device of its profile that was saved), leaving the other profiles' files. "Forget your files" asks the store for every stored profile, so it also removes what another tab stored, and stored files that fail to play are removed when they fail. A browser without OPFS plays the files and keeps none. The files are best-effort site data, which the Storage Standard lets a browser evict under storage pressure. Files the core rejects leave the engine that played, and the status line shows why. VERIFIED: `scripts/e2e.mjs` drops GF1 packs of the tests' synthetic patches, an MT-32 pack the core rejects, an ECW waveset and a stray file on the list, and checks their names and newest-first order; it plays one GF1 pack and then the other in its place, renders a track's WAV with the GF1, keeps the GF1 playing when the MT-32 pack fails, plays the waveset, and loads an AWE32 pack through the "Load pack" button. Where the local build exists, the AWE32 plays and renders a track's WAV; elsewhere the pack needs its module. A second page of the same origin plays the stored devices without asking for files, forgets the stored GF1 alone while the PCI 128 stays stored, deletes a stored pack that fails, and "Forget your files" empties the store. `tests/profile-files.test.ts` checks that the devices' packs of MT-32, SC-55 and ECW files equal `scripts/profile-assets.py`'s for the same files, and `tests/serve.test.ts` checks the `/local/` route on a real server. The e2e also serves `pci128.sf2` to a page of its own, where it exists, and renders a track's WAV on the Sound Blaster 128.

The progress bar is defuss-shadcn's Slider, whose script redraws the filled part only on the user's input: the player sets the fill itself, and holds the bar only while the user drags it, not while it has the focus.

The visualizer is Bergium (https://github.com/kyr0/bergium), vendored in `vendor/bergium/` because it is not published to npm. `demo/visualizer.ts` uses its low-level `createVisualizer` on one canvas; the page offers its Butterchurn pipeline ("Bergium") or none ("No Visuals"), Bergium by default. It hears the synthesizer's `source`, the signal before the volume slider, through a gain of 4, so the picture moves at any volume and four times as strongly as the output's level gave it. It rotates every 30 seconds through the 14 presets of `demo/bergium-presets.json`, which the build takes from butterchurn-presets' base pack into `visualizer/presets.json` (102 KB instead of the 646 KB pack), and shows each new track's title over the picture. The build bundles it into `visualizer/` (197 KB), which the page loads once audio runs.

The build copies defuss-shadcn's runtime and the stylesheets the page uses to `shadcn/`, with its licence. The page keeps its other controls in plain HTML, CSS and JavaScript; a framework would add a second build lifecycle for a single screen without reducing the audio implementation. `build.mjs` copies the package files to `synth/`; edits belong in `src/`, not there. The copy is committed, because GitHub Pages serves this folder from `main` without a build step, so a change to `src/` needs `make build` before its commit.
