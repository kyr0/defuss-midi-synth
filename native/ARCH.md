# Native synthesizers

## SoundFont engine

`synth.c` builds into `vendor/runtime/midi-synth.wasm` (`make wasm`). It wraps TinySoundFont (`tsf.h`, version 0.9, MIT, copied unchanged with its notice at its head) behind a small C ABI: `synth_buffer` and `synth_load` load a SoundFont, `synth_message` plays one MIDI channel message (FFh is a General MIDI reset), `synth_set_preset` selects any bank and program on a channel, `synth_render` renders up to 128 planar frames, `synth_voices` counts the sounding voices, and `synth_preset_*` list the presets.

The module knows nothing of time or byte streams. `src/engine.ts` dispatches complete messages between render calls, so each message acts at its own output frame. The General MIDI reset puts channel 10 on the drum kits of bank 128 and sets channel volume to 100, because TinySoundFont's own reset leaves volume at 127.

The build is standalone (`-sSTANDALONE_WASM`) with memory growth, so it has no JavaScript glue and one import. VERIFIED: over three interleaved rounds on an Apple M5 Max under Node 24, the medians of `-O2`, `-O3` and `-Os` for 32 notes over 20 s of audio lay within 1% of each other (172.7 to 174.4 ms), and `-O3 -msimd128` took 187.2 ms, 8% longer. The build uses `-O2`. VERIFIED: two builds with the same emcc gave identical bytes. A different Emscripten version can emit different bytes, which `scripts/integrity.mjs` then reports until `make wasm` records them.

## FM engine

`fm.cpp` builds into `vendor/runtime/fm-synth.wasm` (`make wasm`, `-O2 -msimd128`, 329,678 bytes). It wraps libADLMIDI 1.6.2's real-time API: `fm_init` sets the rate, the chips (1 to 8) and the embedded bank, `fm_set_bank` and `fm_load_bank` change the instruments (a WOPL file through `fm_buffer`), `fm_message` plays one channel message (FFh resets every channel), `fm_render` renders up to 128 planar frames, and `fm_voices`, `fm_chips` and `fm_bank_name` describe the state. Like the SoundFont module it knows nothing of time and imports only `emscripten_notify_memory_growth`.

`adlmidi/` is libADLMIDI (commit `ad001c83551779934bacd642fce801c51a5b7b4c`) trimmed to the files this build compiles: the MIDI sequencer and every chip emulator but Nuked OPL3 fast 1.8-fast.3 (commit `f44bacb1143cd78d36bacf69fbec8c60a125b3c9`) are left out. The changes to the copies:

- `src/adlmidi_opl3.cpp` knows only the Nuked fast chip; `src/structures/pl_list.tcc` aborts where it threw, since the build has no exceptions; `src/chips/opl_chip_base.h` makes the resampler's members protected.
- `src/chips/nuked_fast/nukedopl3_block.inc.c` is this project's block renderer, included at the end of `nukedopl3_fast.c`, and `src/chips/nuked_opl3_fast.cpp` calls it through `generate32`, then applies the resampler's own integer interpolation. `-DDEFUSS_OPL3_PER_SAMPLE` builds the unchanged per-sample path, against which `make wasm` checks every build (see [../ARCH.md](../ARCH.md)).
- `nukedopl3_fast.c` stops the build with `#error` under configurations the block renderer does not reproduce.

libADLMIDI's contribution rules (its `AGENTS.md`) refuse code generated by language models. The block renderer was written with one, so it stays in this project and is not offered upstream.
